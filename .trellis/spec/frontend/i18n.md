# i18n 准则（前端）

> 加任何一条用户可见文案前先读这里。**三套 locale 必须同步** —— 这一条目前没有脚本守护，靠你自己。

---

## 结构

```
web/src/i18n/index.ts                     # 装配 + 懒加载
web/src/i18n/context.ts                   # useAppI18n()
web/src/i18n/locales/zh-CN/{core,access-keys,group,import,monitor,models,model-prices,settings}.ts
web/src/i18n/locales/en-US/…              # 同名 8 个文件
web/src/i18n/locales/ja-JP/…              # 同名 8 个文件
```

**文件名 = namespace**，由类型锁死（`i18n/index.ts:5`）：

```ts
export const supportedLocales = ['zh-CN', 'en-US', 'ja-JP'] as const
export type AppLocale = (typeof supportedLocales)[number]
export type MessageNamespace = 'import' | 'group' | 'access-keys' | 'monitor' | 'models' | 'model-prices' | 'settings'
```

`core` 是唯一不参与懒加载的（启动即加载）。`namespaces` 数组与 `namespaceLoaders` 映射表**必须同步维护**。

---

## 加载策略

- `core` 在 `main.ts` bootstrap 时 await。
- 其余按路由 `meta.messageNamespaces` 在 `router.beforeResolve` 里加载（`app/router.ts:162`）。
- **同时强制加载 `en-US` 作为 fallback**（`ensureWithFallback`，`i18n/index.ts:173`）。
- 用 `plugin.global.mergeLocaleMessage` 增量合并，`loaded: Set` 去重，`pending: Map` 防重复请求。

## 文件写法

```ts
// web/src/i18n/locales/zh-CN/group.ts
export default {
  groups: {
    title: '分组',
    collection: {
      loading: '正在加载分组',
      filters: { region: '筛选分组', searchLabel: '搜索', reset: '重置条件' },
      connectionType: { label: '渠道类型', all: '全部渠道类型', apiKey: 'API 密钥' },
    },
  },
} as const
```

- **key 是 camelCase，层级按「feature → 页面区域 → 语义」**。
- 根级 key 按文件：`core.ts` → `common` / `auth` / `shell` / `notFound` / `home`；`group.ts` → `groups` / `group`；其余文件各一个同名根（`import`、`models`、`monitor`、`modelPrices`、`settings`、`accessKeys`）。
- **插值用命名参数** `{name}` / `{count}` / `{url}`，无位置参数。
- 数字 / 复数走 vue-i18n 的 `n()`：
  ```ts
  const { n, t } = useI18n()
  t('groups.collection.result', { shown: n(data.items.length), total: n(data.pagination.total_items) })
  ```

---

## 组件里怎么用

```ts
const { t } = useI18n()          // 108 处，从不传 options（没有局部 scope）
const { n, t } = useI18n()       // 需要数字格式化时
```

i18n 控制器本体（切语言、懒加载）通过 `useAppI18n()` 取（`i18n/context.ts`）。

**动态 key 拼接是允许且常见的**，前提是枚举与 key 一一对应：

```ts
t(`groups.collection.status.${group.status}`)
t(`groups.collection.sort.${sort}`)
```

## 新增文案的流程

1. 在对应 feature 的对应 namespace 文件里加 key。
2. **三套 locale 同步加**（`zh-CN` / `en-US` / `ja-JP`）。
3. 组件里 `t('...')`。

⚠️ **缺口提示**：仓库里**没有** key 一致性检查脚本（`web/` 下无 `scripts/`，`package.json` 只有 6 个 script，没有 i18n lint）。key 同步目前纯靠人工 review。漏加时的表现是：该语言 fallback 到 `en-US`，中文会直接缺。

---

## 与后端 i18n 的关系

**两套独立系统，不要混用**：

| | 后端 | 前端 |
|---|---|---|
| 库 | go-i18n v2 | vue-i18n |
| 覆盖 | 仅控制面错误/提示（33 条） | 全部 UI 文案 |
| key | 点分小写 | 嵌套 camelCase |

**接口点只有一个**：后端返回已经本地化好的 `message`，前端**直接展示**。前端只用 `code` 做程序化分支。

→ **前端不得用 `code` 去查自己的 i18n 表重写文案**，那会和后端语言不一致。

---

## 反模式

- ❌ 只加一种语言的 key。
- ❌ 用 `code` 查前端 i18n 表覆盖后端 message。
- ❌ 在组件里硬编码中文/英文文案。
- ❌ 新增 namespace 文件却忘了同步 `namespaces` 数组与 `namespaceLoaders`。
- ❌ 用位置参数插值。

## 验证

```bash
pnpm --dir web run lint && pnpm --dir web run build   # 类型检查会暴露部分 key 拼写问题
make check
```

三份 locale 的 namespace 文件集应完全一致（8 × 3）。新增 key 后自查三份文件的 key 集合。
