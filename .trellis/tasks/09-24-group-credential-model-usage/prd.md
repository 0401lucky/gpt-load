# 按 (凭据, 上游模型) 展示额度窗口内的 token 用量

## Goal

让操作者能在一个视图里看到**某个分组下每个上游 key 的每个模型在当前额度窗口内已经消耗了多少 token**，并同时看到它是否正在冷却、何时恢复，从而判断哪些 `(key, 模型)` 快触顶、哪些还有空间 —— 不再需要逐条凭据点开或从日志里数。

## Background

### 业务背景

- 上游 `cline`（group_id=4，44 个可用凭据）的免费额度按 **key × 模型**每日计算；额度耗尽时返回 429 并写出重置时刻（如 `Try again in 3h 18m`）。
- 2026-09-24 已上线分组级开关 `rate_limit_reset_hint_enabled` 并**在 cline 组开启**，该 `(凭据, 模型)` 的冷却时长改为上游给出的重置时间。因此现在能准确知道每个 `(key, 模型)` 的重置时刻 —— 这既是划定额度窗口的锚点，也是本功能的前提。
- 但操作者仍然看不到**用量**：知道某个 `(key, 模型)` 在被冷却，却不知道它这一轮用了多少、离触顶还有多远。

### 认知边界（必须写进交付说明）

**上游不提供「剩余额度」**。我们从 429 只能得到重置时刻，因此本功能展示的是「**本窗口已用 token**」。任何"剩余"或"百分比"表述都只能是推断值，**不在本版范围内**。

### 生产实测证据（2026-09-24，容器 `gptload2`）

- **用量数据已存在且完整**：`usage_stats` 表 13997 行，覆盖 2026-09-02 起（小时桶）；cline 组近 24 小时有 **116 个 `(credential_id, model)` 组合**，`credential_id=0`（未归属凭据）的行数为 **0**。
- 样本（cline 组近 24h，按输入 token 降序）。注意模型名是**上游模型 ID**：

  | 凭据 | 上游模型 | 请求 | 成功 | 失败 | 输入 token | 输出 token |
  |---|---|---|---|---|---|---|
  | 523 | `z-ai/glm-5.3-flash` | 176 | 172 | 4 | 3,367,595 | 60,559 |
  | 35 | `z-ai/glm-5.3-flash` | 140 | 135 | 5 | 2,854,855 | 75,814 |
  | 445 | `cline-free/mimo-v2.6-flash` | 33 | 33 | 0 | 2,602,361 | 42,727 |
  | 479 | `cline-free/deepseek-v4.1-flash` | 199 | 198 | 1 | 827,195 | 544,948 |

- 冷却中的 `(凭据, 模型)` 共 **27 组 / 21 个凭据**；`credential_counts = {model_cooldown: 21, total: 44, available: 44, cooldown: 0}`。
- **各 key 的重置时刻互不相同**，落在 UTC 00:04–05:41（跨到次日），**不与 UTC 零点对齐** —— 这是选择「以该组合自身周期为窗口」而非「UTC 当日」的实测依据。

## Requirements

- **R1 窗口口径**：以该 `(凭据, 上游模型)` 自身的额度周期为窗口 —— 窗口起点取该组合**上一次已发生的重置时刻**；周期尚未结束时取上一周期起点。窗口内已用 token 是主要展示值。
- **R2 查看维度**：按 `(凭据, 上游模型)` 展示，含输入/输出 token 与请求数；模型维度必须用**上游模型 ID**（与冷却键一致），不得使用客户端模型名。
- **R3 展示位置**：**两套前端的分组详情页**各新增一个「凭据 × 模型用量」矩阵区块，一屏列出该组全部符合条件的 `(凭据, 模型)`。规模参考：cline 组近 24h 为 116 行，需按长列表设计。
- **R4 与冷却状态同屏**：矩阵每行同时给出「是否正在冷却 / 恢复时刻」，避免在两处来回切换。
- **R5 无周期记录时的兜底**：回退到**近 24 小时**窗口。依据：上游额度本身按日计算，“近 24h” 是有原则的近似而非任意默认值；该组合一旦产生周期记录即自动切换为精确窗口。注意这不是边缘情况 —— **上线时所有组合都无该记录**，它是初期默认状态。
- **R6 口径必须可分辨**：每行都要能区分「精确周期窗口」与「近 24h 兜底」两种口径，不允许用同一列标题掩盖（接口下发口径标识）。
- **R7 排序与筛选**：支持按用量排序，并支持筛选（至少「只看冷却中」与按模型分组/折叠），因为行数会到数百量级。
- **R8 两套前端同步**：modern 与 classic 的**分组详情页**都实现该矩阵；classic 侧须遵守其严格投影白名单与三语言文案约定。
- **R9 矩阵内不提供操作**：不在矩阵行内提供「解除冷却」按钮；需要手动恢复时沿用现有管理入口。
- **R10 只读**：本功能不参与调度、选取或冷却判定的任何决策路径。

## Acceptance Criteria

- [ ] AC1 在 cline 组（group 4）的分组详情页，能在一个视图内看到所有 `(凭据, 上游模型)` 的窗口内已用 token 与冷却状态，行数与接口一致（当前约 116 行）。
- [ ] AC2 对有周期记录的组合，窗口起点等于该组合上一次已发生的重置时刻；**同一视图中不同组合的窗口起点可以不同**（用两个重置时刻不同的组合断言，防止窗口被写成按组统一）。
- [ ] AC3 对无周期记录的组合，窗口起点为 `now - 24h`，且接口下发的口径标识为兜底口径，UI 上可与精确窗口区分。
- [ ] AC4 正在冷却的组合，其行的起点为该组合的上一周期起点，并同时给出恢复时刻。
- [ ] AC5 模型列展示为上游模型 ID（如 `z-ai/glm-5.3-flash`），不是客户端模型名。
- [ ] AC6 用量数值与直接查 `usage_stats` 的同窗口整点聚合逐项相等（输入/输出/请求数各一项抽样对齐）。
- [ ] AC7 排序与筛选可用：可按用量排序、可筛出「只看冷却中」、可按模型折叠。
- [ ] AC8 classic 与 modern 两侧的分组详情页都能正常渲染该矩阵，**不出现整页报错**；两套 locale（各三语言）文案齐全。
- [ ] AC9 服务端重启后，周期锚点从检查点恢复，窗口口径不回退为兜底口径。
- [ ] AC10 兼容与门禁：**不新增数据库迁移**（账本保持 24 条）；`internal/health` / `internal/scheduler` / `internal/telemetry` 的依赖边界未被破坏；`make check` 通过。

## Out of Scope

- **不展示「剩余额度」或百分比进度**（上游不提供）。如后续要做「已用 / 触顶估计值」，另开任务。
- 不新增计费/定价能力，不改 `EstimatedCostNanoUSD` 的既有语义。
- 不改按 `(凭据, 上游模型)` 冷却机制本身，也不改 `rate_limit_reset_hint_enabled` 的解析逻辑。
- 不改 `CredentialWindowUsage.vue` 现有的百分比额度窗口语义（订阅类渠道用）。
- 不扩展全局 `/usage` 页的 credential 维度。
- 不含服务器部署与生产配置变更。

## Technical Notes

- 详细设计见 `design.md`（状态模型、接口契约、整点对齐、权衡），执行顺序与验证命令见 `implement.md`。
- 关键约束：本任务**不新增数据库迁移**，窗口锚点放在既有运行时检查点里；锚点的清理**不得**复用 `pruneModelCooldowns`，否则冷却过期瞬间锚点即被删除、功能静默失效。
- 交付形态：接口是新增的，但**后端接口与两套前端的投影白名单必须放同一个提交**，否则中间提交会让未同步的一侧整页报错。
