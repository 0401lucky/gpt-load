## 冷却与可信额度周期

上游将可随订阅额度恢复解除的账号/模型冷却存入 `QuotaCooldownUntil` / `QuotaModelCooldowns`，并使用 `QuotaCooldownGeneration` 防止恢复前的在途错误结果重新写回。fork 的 `ModelCycleStarts` / `ModelNextResets` 是用量统计的可信周期证据，不能与冷却截止混为一体。

合并要求：

- `health.Decision` 同时保留上游 `QuotaCooldown` 和 fork `QuotaResetAt` / `QuotaResetSource`；错误规则应用及已提交请求安全约束不丢弃任一合同。
- gateway 按决策保存额度类或普通冷却，并在同一个身份/恢复代次校验及锁内保存独立可信 reset；不能先写普通冷却再写额度冷却，否则额度恢复无法正确解除。
- 额度恢复只清除额度类账号/模型冷却，保留普通冷却、黑名单、失败状态及可信周期锚点。默认 60 秒或一般 Retry-After 不产生周期证据。
- 模型用量视图中的冷却状态合并两个来源，周期起点仍来自可信证据。只发生额度恢复不能凭空截断统计窗口。
- registry 的复制、保留、身份变更和 checkpoint 捕获/恢复同时覆盖两个冷却来源及 fork 周期。旧 checkpoint 无可信周期版本时保留健康状态但丢弃不可信周期。

以现有 state/health/gateway 用例为基础，补充额度类冷却与可信 reset 同时存在、恢复保留周期、有效冷却投影和过期在途结果被拒绝的交叉回归。

## 其他自动合并区域

检查请求日志最新失败摘要与用量的精确边界归并共存；请求体记录默认关闭且鉴权不扩张。接纳固定上游的 Go 1.27.3、Bifrost 1.13.1、CPA v8.0.36 和精确锁文件，不做额外依赖升级。原有 GHCR main workflow 和 Compose 的 fork 仓库目标保持可用。

上游 CLI `update` 默认下载官方发布包，但代码已拒绝开发版，fork main 镜像使用 `2.0.0-dev.*`。验证该守卫能拒绝 fork 版本且不发起下载；本轮不更改官方 Release 渠道或实际执行自更新。

## 验证与回退边界

按 Makefile 逐项执行完整门禁；本机未发现 make，可在 PowerShell 下执行等价命令并记录。Go 自动工具链下载与 pnpm shim 只作用于进程/临时目录，不改全局配置。修改独立 CPA module 后执行其 tidy/vet 及与 SDK 更新相关的必要回归。

生产数据库不在测试范围。集成分支保留供审查；旧版本回退需要配套升级前的数据库及密钥备份，不改既有生产账本。主会话只暂存本任务文件，保留用户原有未跟踪目录。
