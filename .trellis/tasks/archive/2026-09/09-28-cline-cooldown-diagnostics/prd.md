# 修复 Cline 模型用量漏算与连接测试诊断信息缺失

## Goal

让模型用量页正确统计已记录的周期用量，让管理员通过连接测试直接看到足够的上游错误证据，区分额度耗尽、凭据无效与其他错误。

## Background

- 用户于 2026-09-28 明确选择“两项一起修”。
- 已完成线上只读排查，证据见 research/findings.md：12 个零用量项中 11 个存在被起始小时取整排除的用量，另一个是本周期无本地用量但上游仍拒绝的独立情况。
- F1：internal/control/group_model_usage.go:95、:195、:222 舍弃边界小时。样本 cac8 的 112 次成功、15,662,497 tokens 全被漏算。
- F2：internal/control/credential_probe.go:50、:271、:393、:626 仅保留测试分类，丢失上游错误详情。冷却有真实 429 依据，不属于此次修复对象。

## Requirements

- R1：按每个凭据及上游模型的实际窗口起点统计，包含起始小时和截至观测时刻的当前小时；同一小时内的用量不漏算、不重复。
- R2：保留已有 token、成功/失败请求数及窗口来源语义；无本地用量时仍允许显示 0，不能根据 0 推断 key 无效。明细过期导致不能完整取数时明确标识统计不完整。
- R3：连接测试在已有分类之外展示实际 HTTP 状态码、脱敏且限长的上游错误说明，以及可获得的重试提示；无上游响应时保留安全分类回退。成功结果与恢复操作保持原语义。
- R4：classic 与 modern 同步，中文、英文、日文文案同步。
- R5：计算基于本项目已有数据，读取不得逐 key 发起数据库查询；测试诊断不得暴露凭据、代理认证或请求正文。

## Out of Scope

- 不更改路由、重试、模型冷却判定、周期锚点规则或实际供应商额度。
- 不清除冷却、不补造历史用量、不迁移生产数据；初始本地修复之外的发布/部署按后续明确授权执行。
- 不调查上游账号所有权或判定 475 与其他 key 是否共享额度；仅以现有证据呈现错误。
